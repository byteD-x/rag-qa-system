# RAG-QA 本地可用性与 QA 走查

日期：2026-10-13（Asia/Shanghai）
环境：本地 Vite `http://127.0.0.1:5174`，Gateway/KB 已运行，Chrome in-app browser。
账号：管理员演示账号、成员演示账号；未输出密码或 token。

## 1. 范围、假设与限制

### 已走查

- 登录、登录失败、管理员/成员权限、退出入口。
- 业务总览、统一问答、新对话、范围选择、引用/拒答、反馈、会话重命名/删除入口。
- 知识库治理：已有文档、版本元数据、新建表单空校验、上传入口、文档删除入口。
- 知识治理工作台、批量 JSON、检索测试、知识库运维、多源同步。
- AI 模拟面试、Agent/Prompt/模型/监控/工具/记忆/成本/场景/缓存/API Key/Webhook/PII/指令市场/A-B/Agent 编排、审计日志等已注册路由。
- 默认、空、成功、错误、无权限、移动端、慢路径的可观察状态；用 DOM/截图/控制台日志确认。

### 关键假设

- 这是面向真实互联网用户及 HR/面试官的可用产品，而不只是管理员内部原型。
- “支付/下单/退款/取消订阅”和“注册/找回密码”是用户要求覆盖的任务；若产品明确不提供，应在产品范围中声明。

### 无法安全执行或需人工确认

- 未上传真实个人文件、未提交真实 Webhook/Notion/SQL 凭据、未创建 API Key、未删除真实知识库/文档；这些会产生外部或不可逆副作用。
- 未在真实 NVDA/JAWS/VoiceOver 上验证，只做 DOM/键盘语义检查；未执行 axe/Lighthouse。
- 未人为断开网络、注入超时或并发压测；需补充自动化故障注入。
- 支付、退款、订阅、账号注册/找回没有前端入口，无法验证完成路径。

## 3. Think-aloud 走查记录

### 轮 1：首次 + 急躁 + 移动 + 慢网

1. **入口**：我打开页面，看到“登录”和“演示账号”。我以为可以注册或找回密码，但页面没有入口；只能使用已有账号。首次用户会停顿并怀疑这是内部系统。
2. **登录**：点击“管理员”自动填入账号，再点“进入工作台”，登录成功并跳到业务总览。成功 toast 明确，但没有说明下一步是“先建库/上传/提问”。
3. **快速提问**：进入统一问答后看到大量重复历史会话。新用户不知道哪个是示例、哪个是自己的。打开新对话能看到建议问题，理解成本低。
4. **发送**：输入不存在的问题，按 Enter 发送；回答很快返回拒答和引用。等待中仅显示“正在检索…”，没有取消/重试；移动端输入框位于视口下方，首屏找不到输入框，任务被阻塞。
5. **知识库**：进入知识库治理，页面信息密集且表单很长。上传入口可见，但真实文件上传未执行；版本号、起止日期控件在运行时高度为 0，无法填写。
6. **情绪**：登录顺利，但移动端无法继续提问、平台页报错时只看到空状态，容易从“想试试”变成“不敢继续”。

### 轮 2：回访 + 专家 + 追求效率

1. **回访找会话**：历史列表只有标题，没有时间、知识库、最后一问或搜索/筛选；大量 `eval-single`、`det2` 重复，专家无法快速定位上次工作。
2. **范围切换**：点击“范围：单库”可切换单库/多库/全库，弹层有知识库和限定文档。控件本身可理解，但 `1/1` 计数含义不解释；回答策略开关的当前状态依赖开关颜色/位置。
3. **看结果**：回答区显示拒答、依据、引用和召回耗时，可信度线索充分；但仪表盘显示“Refusal 100%”同时“暂无无命中查询，知识库覆盖良好”，数据叙事冲突。
4. **治理/调试**：检索测试的 `Limit` 默认值存在于模型但控件不可见；专家不能调整召回数量。批量 JSON 预填了示例，但下方仍提示“请提供 documents JSON”，造成不确定。

### 轮 3：键盘 + 屏幕阅读器 + 低视力

1. **Tab**：全局有跳到主内容链接，登录字段有可读标签；但统一问答发送按钮和移动导航按钮没有 accessible name。
2. **移动聊天**：聊天侧栏通过 transform 移出屏幕，但其中几十个会话按钮仍在 Tab 顺序中，键盘用户会逐个聚焦看不见的控件。
3. **动态回答**：`正在检索…`、流式回答、错误 toast 没有 `aria-live`/状态区域，屏幕阅读器不会可靠获知“已完成/失败/需要补问”。
4. **弹窗**：移动抽屉没有显式关闭按钮；Element Plus 关闭按钮/标签仍出现英文 `Close this dialog`、`Close this tag`。低视力用户在长表单中缺少固定的当前步骤/错误定位。

### 轮 4：错误 + 异常 + 边缘数据 + 权限

1. **错误登录**：错误邮箱/密码最终提示“登录已失效，请重新登录”，没有区分凭据错误、网络错误、账号锁定或服务不可用。
2. **空表单**：新建知识库空提交能提示“请填写名称”；添加数据源空提交返回英文 `request validation failed`，字段没有高亮，用户不知道缺什么。
3. **服务错误**：多源同步加载时实际收到 500，却同时显示“暂无数据源”和两条“请求失败，请稍后重试”；空状态和错误状态混淆，没有页面级重试按钮。
4. **404 页面**：API Key、Webhook、PII、A/B 实验、Agent 编排页面分别出现 `Not Found`，仍渲染“0”或空表格；用户可能误以为确实没有数据。
5. **权限**：成员直接打开 `/workspace/kb/operations` 被静默重定向到业务总览，没有“无权限”说明或申请入口；用户会重复点击并认为系统失灵。
6. **极端/并发**：未执行真实超长文件、特殊字符、断网、超时和双击上传；需自动化补测，不能据此声称通过。

### 轮 5：内容 + 信任 + 商业伦理

1. **证据**：拒答明确说明证据不足，引用入口可展开，方向正确；但引用来源的版本/页码等上下文不总在首屏，HR 判断依据需要额外点击。
2. **敏感数据**：PII 配置页和 API Key 页存在，但后端目前 404；这比“保存成功后失败”更安全，却没有告诉用户功能暂不可用。
3. **不可逆操作**：会话删除有二次确认并提示不可恢复，但没有撤销；文档/知识库/连接器删除需人工确认，未实际执行。
4. **商业任务**：源码和路由没有支付、订单、退款、订阅、取消订阅、注册、找回密码能力。若这些是业务必需，任务从入口就无法开始。

## 5. 按任务/页面汇总

- **注册/登录/找回**：登录可用；注册、找回密码缺失；错误提示过于笼统。
- **搜索/筛选/查看**：问答范围可切换；历史会话无搜索/时间/筛选；检索 Limit 控件不可见；仪表盘计数口径不一致。
- **创建/编辑/提交**：新建知识库空校验可用；版本号/日期不可编辑；数据源 JSON 空提交错误不可行动；真实上传/保存成功未做副作用测试。
- **支付/下单/退款**：无入口、路由或 API 证据，标记“未实现/需产品确认”。
- **设置/权限/删除/取消订阅**：权限路由静默重定向；会话删除不可撤销；API Key/PII/Webhook 等平台设置后端 404；取消订阅无入口。
- **错误/异常/找回**：连接器 500 被渲染为空；平台 404 被渲染为 0/空表；loading/重试/超时/离线仍需补测。

## 6. Top 10

1. UX-001：关键 Element Plus 控件未注册，多个核心任务无法完成。
2. UX-002：移动端问答输入框完全出视口，目标用户无法提问。
3. UX-005：连接器 500 与空状态混淆且无重试，数据同步风险高。
4. UX-006：多项平台能力后端 404，页面仍伪装成空数据。
5. UX-009：流式回答不向屏幕阅读器播报。
6. UX-004：移动关闭侧栏的不可见按钮仍进入键盘焦点序列。
7. UX-003：发送/移动导航图标按钮无可访问名称。
8. UX-010：总览与治理数据口径冲突，破坏 RAG 效果信任。
9. UX-007：注册/找回/支付/退款/订阅链路缺失（若属于产品范围则为阻塞）。
10. UX-008：无权限静默跳转，用户无法理解或恢复。

## 7. 快速修复 vs 结构性改进

### 快速修复（低改动、高收益）

- 补齐并统一注册 `ElTooltip/ElDivider/ElInputNumber/ElDatePicker/ElSkeleton/ElSlider/ElTabs/ElTabPane/ElPagination/ElCheckboxGroup` 等组件。
- 给两个空图标按钮加 `aria-label`、`title` 和 disabled/发送状态。
- 移动端聊天 composer 改为父级 flex 内固定底部，修复 `height: 100vh` 嵌套裁切。
- 连接器/平台页面增加 `error` 状态、一次性错误提示、重试按钮；不要在失败时复用空状态。
- 把 `request validation failed`、`Not Found`、`No Data`、Element Plus close 文案映射为中文可行动文案。
- 修复治理页乱码，统一 UTF-8 和中文术语。
- 无权限时显示 403 说明和返回/申请路径；保留原始 URL。

### 结构性改进

- 建立“页面状态模型”：loading / empty / partial / success / error / forbidden / offline / timeout，所有数据页复用。
- 建立前端启动 smoke：逐路由渲染、控制台零 `Failed to resolve component`、关键控件尺寸>0、按钮有 accessible name。
- 建立问答可访问性模式：`aria-live=status`、流式回答完成通知、错误焦点、移动抽屉 focus trap。
- 为会话和知识库建立搜索/筛选/分页/更新时间/范围标签；删除采用回收站或撤销。
- 对指标统一口径和数据范围，展示更新时间、降级原因、trace_id；用真实 seeded 数据做前后端一致性回归。
- 产品层明确账号、账单、订阅边界；若不提供，应在登录和设置中显式说明，而非留下“看似缺失”的入口。
