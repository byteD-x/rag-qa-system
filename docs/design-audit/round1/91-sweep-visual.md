# 91 跨页扫描：视觉规则与 design token 符合性

扫描范围：apps/web/src 下全部 .vue（45 个，排除 *.test.ts）与 3 个全局 css（apps/web/src/style.css、apps/web/src/styles/responsive-enhancements.css、apps/web/src/styles/theme-extras.css）。本报告只给跨页结论，不逐页展开。

## 唯一用户任务

任意角色在打开任意业务界面、首次看到首屏的 3 秒内，要判断出这一页的主对象和主动作并直接完成它。

## 完成该任务的必要步骤

1. 读页头标题与副标题，确认自己在哪一页（apps/web/src/components/PageHeaderCompact.vue:4、:5-7）→ **keep**
2. 在页头右侧找到本页主动作（如刷新 / 新建，apps/web/src/views/kb/KBGovernanceView.vue:9-11）→ **keep**
3. 读统计卡组获得数字上下文（3-5 张 stat-card / summary-card / metric-box，apps/web/src/views/platform/AgentMonitorView.vue:15-33、apps/web/src/views/kb/KBGovernanceView.vue:14-20、apps/web/src/views/EntryView.vue:79-172）→ **demote**（数字不需要独立卡片表面，与页头副标题重复）
4. 进入主区第一个面板，找到输入或操作入口 → **merge**（筛选条与工具栏在多页是两套控件，apps/web/src/views/kb/KBGovernanceView.vue:22-35 的 toolbar-row 与 :5-8 的 viewMode 切换职责重叠）
5. 依次读完若干个"最近一次…结果"面板才能回到列表（apps/web/src/views/kb/KBGovernanceView.vue:94、:114、:134、:191、:200）→ **drop**（同页最多 8 个层叠结果面板，用户必须滚过它们）
6. 区分"可点的卡片"与"只是分组的框"（apps/web/src/views/kb/KBGovernanceView.vue:916、:926、:928、:929 四层同构表面）→ **drop**（删掉嵌套层级的表面属性）
7. 相信看到的状态色（apps/web/src/views/platform/CostDashboardView.vue:246、:252 的 --blue-400 未定义导致条形不可见，apps/web/src/views/platform/AgentMonitorView.vue:517 的 DAG 状态轨不可见）→ **keep**，但必须先修

## 结论摘要

- 视觉规则层面最严重的问题不是"过度装饰"，而是**一整套 token 是空的**：`--blue-400`、`--red-400/500/600`、`--green-400`、`--orange-400`、`--blue-100/200`、`--bg-body`、`--color-primary` 在 apps/web 内零定义（含 element-plus/dist/index.css 也无），12 个文件约 40 处引用因此整条声明失效——成本条形图、模型成本条、每日趋势柱、DAG 状态轨直接不可见，用户会把"渲染失败"读成"数据为 0"。
- 字号刻度形同虚设：331 条 font-size 声明中只有 38 条（11.5%）走 `--text-*`，41 个不同字号值里 13px（61 次）、11px（28 次）、14px（19 次）、16px（15 次）完全在 4 档刻度外；最密的 3 页同屏 8 档字号。
- 圆角、颜色、阴影各有第二套写法：23 种 border-radius 值（8px 字面量 21 次对应 `--radius-sm`，12px 9 次对应 `--radius-md`，另有刻度外的 10px 13 次）；82 个 hex + 53 个 rgb/rgba；11 处裸 box-shadow 绕过 `--shadow-*`。
- 层级靠"再加一层带边框和底色的表面"表达：10 个界面出现 2-4 层同构卡片嵌套，最深一处是 4 层（apps/web/src/views/kb/KBGovernanceView.vue:916→926→928→929）。
- 深色模式只有 5 个 `[data-theme='dark']` 选择器（全在 apps/web/src/styles/theme-extras.css:14、:83-86）；apps/web/src/style.css:658、:682、:700 用 `!important` 把按钮/输入框/文本域底色钉成白色，深色模式下是浅底浅字。
- 动效方面已确认的全局问题未重复统计；本次新增 8 处给 width/height 加过渡、8 处给 box-shadow 加过渡、30/56 条 transition 使用被禁止的 CSS 预设曲线。

## 存疑

- `.dag-node` 左边框失效的推论基于 CSS 自定义属性规范（未解析的 `var()` 使整条声明在 computed-value 阶段按 unset 处理，而非回退到更低优先级的 `border` 声明）。我没有在运行环境复现，**必须**在 devtools 里检查 `.dag-node` 的 computed `border-left-style` 是否为 `none`。若浏览器行为与规范不符（仍显示 1px 全边），则该条降级为"仅状态色失效"。
- 深色模式的具体呈现（输入框白底 + 浅色文字的可读性）需要真机渲染确认。我的依据是 apps/web/src/style.css:682/:700 的 `!important` 白底 + apps/web/src/utils/theme.ts:17 把 `--text-regular` 改成 #cbd5e1，且 apps/web/src/style.css:69 把 `--el-text-color-regular` 绑到它。EP 内部到底用哪个变量渲染输入文字（`--el-input-text-color` 还是 `--el-text-color-regular`）我未核对 EP 源码，无法确认最终对比度数值。
- 「首屏元素数」是静态估算：口径为模板一级子元素数 + 不在 el-dialog/el-drawer/非首个 el-tab-pane 内的表单控件与按钮数（脚本按标签深度统计，自闭合与 void 标签已排除）。真实首屏可见量取决于视口高度、字体与是否展开折叠项，需要实际渲染（1440×900 与 375×812 各一次）才能定论。全仓 ranking：KBGovernanceView 43、KBUploadView 27、KBDocumentView 21、ModelProviderView 15、KBOperationsView 15、AuditView 13、CacheManagerView 12、InterviewView 11、PiiConfigView 11。
- 「同屏字号层级」同样用"单文件 style 块的 font-size 去重值个数"做代理。它高估了同屏可见量（例如 el-dialog / el-drawer 内的字号会被计入，但它们不同屏），所以 KBGovernanceView（2 档）这类低值可信、8 档的高值需要渲染核对。已确认需要核对的高值：AgentMonitorView 8、CostDashboardView 8、ChatMessageItem 8、EntryView 7、CacheManagerView 7。
- apps/web/src/styles/responsive-enhancements.css 里 `.el-progress-bar__inner--anim`（:631-633）的修饰符在 element-plus 中是否存在我未核对，疑为死规则；`.el-slider__bar` 的 `height` 过渡是否与 EP 自带过渡冲突也未核对。该文件另有 30+ 个选择器零使用（已在全局清单内，未重复报告），但零使用清单与实际存活规则混排在同一段，删改时需要逐条确认，否则会误删仍在生效的 EP 内部覆盖。
- `--color-primary`（apps/web/src/views/kb/KBConnectorsView.vue:461）与 `--bg-body`（apps/web/src/views/kb/KBChunkReviewView.vue:265、apps/web/src/views/platform/PromptTemplateView.vue:259）也可能是留给"未来主题包"的占位命名。若是，需要写明来源；若不是，按未定义变量修复。
- 圆角/间距/字号的"应归并到哪一档"是设计决策而非代码事实：例如 14px 间距归 12 还是 16，13px 字号归 12 还是 15，会改变 KBDocumentView、AgentMonitorView 这两页最密界面的行高与换行。我倾向"就近归并 + 每页截图比对"，但最终需要设计负责人确认目标档位。
- 本报告未做任何源码改动（`git status --porcelain` 中只有 docs/design-audit/ 未跟踪目录）。文中的"出现次数"均由脚本在 apps/web/src 下全部 .vue 与 3 个全局 css 上统计（脚本按 `-Include *.vue,*.css` 取文件，因此 *.test.ts 与 api/*.ts 未进入任何计数，font-size/颜色/圆角/间距的分母不含它们）；`node_modules` 与 `dist` 只在核对 `--blue-400` 是否为 element-plus 自带变量时查过 element-plus/dist/index.css（未命中），其余统计不含依赖目录。
- 「卡片套卡片」的判定口径是"同一条祖先链上出现 ≥2 个同时具备 background + border 或 border-radius + padding 的表面元素"。我只对文中列出的 10 组做了模板 + 样式双向核对，未逐页穷举；若某个我未列出的界面也存在嵌套但内层靠 `!important` 覆盖掉了表面属性，会被漏掉。验证方法：对每个 `.vue` 的 `<style scoped>` 提取"bg+border+radius+padding 四要素齐全"的规则，再看其对应模板节点是否有同样四要素的祖先。
